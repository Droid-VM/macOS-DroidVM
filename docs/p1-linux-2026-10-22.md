# 独立 Linux 构建链与本地 owner 策略（2026-10-22）

代码提交：`2e5b522`（本地 owner 策略）、`31c7ace`（独立 Linux 构建链）。文档仅保留本地。

## 完成与边界

全部新增文件、工具链、构建树、Darling 可写 home、产物与证据均在 macos。ios 只在一次性导入时读取；导入来源及文件 SHA256 在 `configs/linux-imports.json`，工具文件清单在 `toolchains/linux/import-manifest.json`。系统 LLVM、Docker 和现有固定 Docker 镜像作为宿主工具使用，未修改 ios 容器。

独立容器 `macos-appleclang` 使用镜像 `sha256:34c45909102c90bc2ae66c98e690d038f479255966c814b59d284004f0185dbf`，mldr SHA256 与已修复版本一致。容器 bind mount 仅涉及 macos；工作目录与 Apple 工具路径不指回 ios。此轮复用本机已存在的固定镜像，没有重新构建 Docker 镜像。

真实 AppleClang C/C++ XNU 类型内建、usage semantics、ARM64 对象输出通过。XNU 首次 bootstrap 编译与真实 IIG 代码生成完成；第一次链接因空 corecrypto 占位归档停止属于上游构建顺序，随后 7 个真实归档均完成，最终源码内核链接成功、未解析符号为 0。NativePrelink 生成候选 kernel.macho，大小 53751808 字节，SHA256 `020b05064ab1b452ff0b24eb4cf1fdedc3482efde7a55b70048e0ec46a701c94`。

**不是可启动 macOS 内核验收。** 本次为裁剪原生存储/显示/owner 路径的 reference candidate，仍使用 iPad7,1 / 21H461 的原始 kernelcache。预链接报告的 `instruction_relocation_complete`、`abi_qualified`、`loadable`、`runtime_qualified` 全为 false；不能把成功生成文件等同于这些资格通过，也不能直接部署。尚未构建完整 guest、EFI 启动盘或 macOS 根盘。

本地 owner 工具已在 12800 字节诊断镜像上完成 RSA3072 签名、独立 C 验证器验签及 4 个块（含 512 字节尾块）检查。单字节篡改、错误卷 UUID、generation 回退均拒绝。仅验证本地 owner 合约；未读取 APFS UUID，不代表 Apple 信任链或 macOS 根盘验证。私钥只存在忽略的 out/owner-check/keys 下。

## 操作入口

```sh
cd /home/qiuqiu/crosvm/macos
# 一次性导入；目标已存在时拒绝覆盖，不需重复执行。
python3 scripts/import-linux-toolchain.py --reference ../ios
python3 scripts/start-linux-runtime.py
python3 scripts/prepare-sources.py
python3 scripts/build-linux.py prepare
python3 scripts/build-linux.py build -j 8
```

`prepare` 修改的是 `out/linux/UniXNU` 和 `out/linux/device-reference`，`sources/` 保持锁定与干净。`tree` 装配明确传入 kernel 引用集，避免普通 tree 命令漏掉 refer/xnu。必要补丁严格应用，失败即停止。LZFSE 源码新增到 source lock，库输出 `out/linux/liblzfse.so`。

本轮暴露并处理的准备问题：普通 tree 未链接 refer/xnu；owner 工具导入 Python 模块产生 source 子模块 pycache（改为禁止字节码写入，已清理本轮生成缓存）。导入的补丁原样保留 context 空行和 Makefile tab；对它们运行普通 diff 空白检查会报告补丁文本自身的格式，未剥除有效 context。非 patch 代码 diff 检查通过，补丁已由实际构建验证。
